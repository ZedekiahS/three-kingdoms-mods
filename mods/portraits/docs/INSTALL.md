# 安装、换电脑恢复与回滚

## 1. 换机要带什么

GitHub 仓库包含自己的代码、27 人原画、重画样稿、人物键、PNG 导出逻辑和经验文档。不要只复制一张图片，以为放进 data 就会被游戏读取。

新电脑安装游戏及 MTU；不要复制别人整套 Steam 目录。确认游戏 1.7.2.0、MTU 3.3；其他版本先重新审查。Steam Workshop 的 MTU 文件一般在 `steamapps/workshop/content/779340/1812159400/[mod]Lady_bian_FLC.pack`。

安装 Git、Python 3.11+、Node 22+、7-Zip。克隆合集仓库后先进入 `mods/portraits`，再执行本项目 README 中 `npm ci` 与 `tools/rebuild.py`；下文所有构建命令均在该子目录运行。使用自己的 `--game-data`、`--workshop`、`--sevenzip` 路径。构建不修改游戏目录、不修改存档。

首次构建需要从本机包读取目录和开局，所以纯源码下载后没有现成 `.pack` 是正常的。Node 的 sharp 有本机二进制依赖，请在新机器 `npm ci`，不要复制旧 node_modules。构建产生的本地路径记录只在被忽略的生成目录里。

## 2. 四个输出包的作用

| 文件 | 用途 | 安装规则 |
|---|---|---|
| `syc_portraits_assets.pack` | 27 人旧实验图片底包 | 当前三人修复依赖它；其余人物并未验证可用 |
| `syc_portraits_route_probe.pack` | 三人分层路径、透明装备、头像定位修复 | 必须启用并置于底包上方 |
| `syc_portraits_mtu33.pack` | 基于本机 MTU 的人物/美术/开局绑定 | 玩 MTU 时用 |
| `syc_portraits_vanilla.pack` | 基于本机原版的对应绑定 | 玩原版时用；不可与 MTU 绑定同时启用 |

退出游戏，将选中的三个包复制到游戏 `data` 文件夹。

MTU 组合自上而下：

1. `syc_portraits_route_probe.pack`
2. `syc_portraits_assets.pack`
3. `syc_portraits_mtu33.pack`
4. MTU 简体中文补丁（若使用）
5. MTU 主包与原有必要附属包

原版组合用 `syc_portraits_vanilla.pack` 替代第三项，关闭 MTU 相关包。

启动器排序只是配置；实际启动后检查游戏根目录 `used_mods.txt`，确认真的载入。不要把该文件当作需要手工修改的安装配置。

## 3. 存档与测试

首次更改人物美术绑定时用新测试战役：已有存档可能保留旧的美术编号。仅更新同路径图片（例如本次三人的头像）时，原测试存档通常可继续验证，但仍需完全退出并重启游戏。

逐人查看府署列表、左侧半身、人物详情全身、人物列表，以及实际需要的其他头像场景。当前不是全角色验收完成的补丁。不要把成年人的显示结果外推到儿童/成年转换，不要把一张府署图外推到所有页面。

建议先只加载 MTU 与这三个测试包。完成后再加入大集结等其他 Mod，一次加一组，保留 used_mods、文件哈希和截图。静态路径不重叠不能证明脚本和开局不会冲突。

## 4. 旧测试文件与冲突

本机曾有 `zz_syc_harem_preview_v2.pack`（movie 类型）覆盖 startpos，即使不在普通勾选列表中也可能自动载入。该文件在原机器已改名为 `.pack.disabled_for_portraits`。新机器不需要它，不要把整个旧 data 文件夹无差别搬来。

不要盲删所有 `zz_` 文件：例如旧环境的 quick-start 跳过片头包和后宫开局包作用不同。查实际包内容后，只禁用具体冲突文件，并保留可恢复副本。

## 5. 更新被占用与回滚

Windows 报“文件正由另一进程使用”时，先退出游戏，等待进程结束，再复制。不要在运行中强杀或强行替换文件。这次每次遇到占用均由用户退出后更新；拷贝后用 `Get-FileHash` 与构建输出比较。

卸载时退出游戏，在启动器关闭三个 syc 包，移走自己安装的这些文件。恢复之前明确备份过的加载配置；不要改用户存档。旧存档受绑定变更影响时，回到改动前存档/配置测试，不能保证卸载后继续运行同一实验存档。

## 6. 可复现性的边界

构建后运行 `python tools/verify_build.py`，检查包结构、三人图片路径、绑定修改范围及文件哈希。2026-11-08 已在这个公开仓库目录中独立安装依赖并完整重建，四个输出包与原工作目录版本逐字节一致，记录见 [重建验证结果](evidence/public_repo_rebuild.json)。这是构建和静态回归通过，不是新增的游戏内验收。

锁定 sharp 依赖可以减少裁切差异；游戏、MTU、schema、7-Zip 版本不同仍可能影响输出。记录 `dist/build_receipt.json` 与 SHA256SUMS，不能只比较文件大小。原机器已安装三人修复包的历史哈希：

`19540692caa727c2d04a7ae50c594700b1daf7b1b37d033469ac4b4c22274fa0`

这是当时三人修复包的证据，不是任意版本都必须相同的标准。画风 v2–v5 试稿没有安装到该包里。
