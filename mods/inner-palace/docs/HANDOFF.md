## 已定位问题与修复依据

- **无职位**：新增 DB/UI 不会自动建立战役里的职位实例。原版开局在两个政体的 CHARACTER_POSTS 列表保存 CHARACTER_POST，必须按原格式加入，并更新分配计数器。仅沿用刘表三种太学职位只能验证原生操作，不能满足全汉派系和独立 14 位。
- **袁术无职位**：只修改吕布/刘表开局不够；现有生成器从 factions 表选择汉文化派系，处理 10 份原版开局，保留其余派系与原职位。
- **空位逐个出现**：原生多人职位列表只生成当前可用位。固定格子改为 14 个唯一职位键，每键上限 1，UI 分成五组。
- **配偶撤位后消失**：NoblesCharacterList 不含全部家族配偶；改用 CharacterList，并让君主配偶作为已婚例外。
- **更换名单仍漏人**：隐式 Filter 中 `IsContextValid(SpouseContext)` 被解析到 CcoStaticObject，日志明确报上下文错误。改为 `(x) => ... IsContextValid(x.SpouseContext)`；Python 逻辑测试不能替代游戏表达式验证。
- **撤位不离婚**：原版 unassign_from_post 和 divorce 是不同动作。历史实测各自只改变职位或婚姻，必须联合处理。当前 `harem_exit.py` 复制原版离婚条件、费用与关系 payload，加入原版撤位组件；只是实现候选，不代表已验证执行顺序或原子性。
- **载入崩溃**：重写整个 actions_list、改写原生动作执行目标的两类尝试失败。失败源码保留在 evidence 下。原版操作 UI + 新名单 + DB 动作的隔离包能加载，因此目前把排查范围缩小到 UI 连接；尚未证明唯一崩溃根因。

## 当前源码分工

- `build_court_copy.py`：从本机 CA 原版 UI 克隆独立页，构建名单、原生卡片、固定布局、职位与效果表。
- `build_lu_bu_test.py --all-han --fixed-slots`：历史文件名，当前参数实际构建全汉文化/10 开局，不只是吕布。
- `patch_native_posts.mjs`：CAAB 实例与压缩外壳最小适配、结构校验。
- `spouse_queen.lua`：按配偶关系初始化皇后，保存每对配偶标记，避免刷新夺回玩家改封。
- `harem_actions.py`：最终候选只改模板过滤及标签；原版枚举、命令、有效性、效果提示和确认执行不改。后宫外隐藏新增动作；后宫配偶显示联合退出；未实际结婚者显示普通「移出后宫」。
- `harem_exit.py`：CA 原版离婚派生 action/payload + 撤位；保留原版费用与关系后果，不假造 Lua 离婚接口。
- `native_court_diagnostic.lua`：仍为诊断版，故意保留旧失败表达式作对照，日志可能有预期错误；发布前应去掉这些对照探针。
- `verify_*.py`：结构/候选/任职边界检查，不是实机验收。
